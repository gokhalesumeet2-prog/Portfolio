Meditation that adapts to how you feel

Part I got people coming back. Then they opened the app, met a library, and left. This replaces browsing with matching: two small questions, one practice, and a sentence explaining why that one, so the decision costs two taps instead of five minutes of self-diagnosis.

01 The problem

The drop-off happens on the screen before the session.

Meditation apps front-load a decision at exactly the moment a user has the least capacity to make one. Someone opening the app anxious at 11pm is asked to browse categories, compare durations and read descriptions. That is cognitive work, and it competes directly with the state they are trying to leave.

Choice is presented as generosity. For a stressed user, a large library is friction.

The library model

  • The user must self-diagnose, then translate that into a search
  • Every option looks equally valid, so none feels correct
  • Decision cost is highest exactly when the user can least pay it
  • Success depends on already knowing what you need

The matched model

  • Two taps, a feeling and a duration, and the system decides
  • One recommendation, with its reasoning stated in plain language
  • Time of day is inferred, never asked
  • The app carries the expertise so the user doesn't have to

02 The recommendation engine

Small enough to explain in a sentence.

A feeling maps to a mudra; time of day acts as a corrective layer. If the clock says it's late and the mapped mudra is an energising one, the system swaps it for a wind-down gesture, and tells the user why. Nothing sits behind a black box, so every recommendation carries its own justification.

03 The mudra system

Ten gestures, drawn rather than photographed.

Ten mudras cover the emotional range onboarding asks about. Each is defined by which fingertips meet the thumb, which meant the entire library could be drawn programmatically as a schematic hand rather than shot as photography. Consistent, accessible, instantly re-skinnable, and a fraction of the production cost.

04 Design decisions

Three calls that shaped everything else.

Ask for a feeling, not a category

Onboarding collects plain-language states, overthinking, burnout, poor sleep, because that is the vocabulary users already have. Translating that into a practice is the product's job, not the user's. A category list would have been easier to build and would have moved the work back onto the person least able to do it.

Kept

Always show the reasoning

Every recommendation carries a sentence naming the inputs that produced it. Stated reasoning is what turns an algorithmic guess into something a user will follow, and it constrains the model, because a rule you can't explain in one line doesn't get to exist.

Kept

Draw the gesture, don't film it

Schematic vector hands render at any size, need no localisation, and highlight only the contact points that matter. Video was the assumed default and would have cost a production pipeline, a re-shoot for every addition, and a comprehension problem across cultures that Part I had already measured.

Kept

05 End-to-end flow

Eight screens once. One screen after that.

First run takes a user from launch to practice in eight screens, two of which are skippable. Every return visit opens on Home, where the recommendation has already been calculated, the cost is paid once, not daily.

07 What this establishes

Two parts, one argument.

  • Decision cost cut to two taps. A feeling and a duration, with time of day inferred rather than asked. Browsing a library is removed from the daily path entirely.
  • A ten-mudra library with zero photography. Every gesture is a parametric vector diagram, so content scales without a production pipeline.
  • Transparent recommendations. Each suggestion states the inputs behind it, including when a late-hour rule has overridden the obvious match.
  • A working prototype, not a static comp. The logic is real and testable, which makes the assumptions falsifiable before any engineering investment.

Part I proved reinforcement brings people back. Part II removes the obstacle that met them when they arrived. Together they make a single argument. Retention is a design problem at both ends of the session, not just at the notification.

NOT YET MEASURED. The prototype is functional and the logic is testable, but this has not run with a user cohort. The next honest step is a two-week diary study comparing matched entry against library entry, that is the study that would either confirm this or kill it.
